# New project page: implementation plan

Spec: `docs/superpowers/specs/2026-11-01-new-project-page-design.md`. Four parts, each green
(`cargo fmt`, `clippy -D warnings`, the crate's tests) before the next.

## Part 1: core rules (`crates/core/src/stack_builder.rs`)

1. The options macro: an enum per category with `ALL`, `id()`, `parse()`, serde by id.
2. The catalog, in upstream's category and option order: name, description, default,
   experimental. `CATEGORIES`, `options(category)`, `option(category, id)`.
3. `Stack` (with `Default` = upstream's `DEFAULT_STACK`), `PRESETS` (MERN, PERN, T3, Uniwind).
4. The helpers of `packages/types/src/compatibility.ts`, private to the module.
5. `sanitize`, `analyze` (upstream's `analyzeStackCompatibility`, branch for branch, same
   messages), `resolve` (10 passes at most), `disabled_reason` (`getDisabledReason`),
   `select`/`remove` (`getTechSelectionUpdate`/`getSelectedTechRemovalUpdate` +
   `applyStackUpdate`), `selected` (`getSelectedTechs`), `desktop_note`.
6. `command` (pinned runner, `formatProjectName`, upstream's shell quoting, `--yes` only for the
   default stack with bun), `run_command` (`npx -y`, `--directory-conflict error --open none`,
   `--manual-db` where the setup would ask).
7. `validate_project_name` (upstream's `ProjectNameSchema` on the basename, plus control
   characters, which the CLI refuses), `Choices` (a partial stack by CLI flag names).
8. Tests: goldens, upstream's CLI rejection cases, the differential fixture
   (`crates/core/tests/fixtures/better_t_stack.json`, generated by running upstream's
   TypeScript; see the fixture's `commit`).

`crates/core/src/new_project.rs`: `Remembered` load/save (`new-project.json`), default
location, first free name, `target` check, `created` check, headless `create`.

## Part 2: the page (`crates/app/src/new_project_page.rs`)

1. State: stack, last changes, name and filter inputs, location, package managers detected and
   the one picked, cursor, scroll handles, measured width, create state.
2. Header, left column, right column with sections and cards; logos (`assets/stack_logos/`,
   `assets.rs`, Lucide fallback).
3. Keyboard: `NewProjectPage` context in `catalog::init`; filter, ↑/↓, ↩.
4. Remembered state written on every change (best effort, off the UI thread).
5. Tests: picking, disabled card, filter, keyboard, layout at 720 and 1470.

## Part 3: create flow

1. `NewProjectEvent::{Create, Open}`; `workspace/new_project.rs` opens the tab, runs the job,
   hands the terminal to the page, opens the project.
2. The page polls `job_status`, checks `package.json`, shows Creating…/failed/Try Again.
3. At work: `at_work` registry, `guard.rs`, `flags()`/`close()` in the workspace.
4. Welcome row, File menu item, title-bar button, `ctrl-cmd-n`.
5. Tests: refusing an existing folder, success opens, failure says so, the tab counts as at
   work while creating.

## Part 4: agent and CLI parity

1. `Page::NewProject`, `Command::NewProject`, round-trip tests; `control.rs` arms.
2. `crates/mcp/src/new_project.rs`: `stack_options`, `stack_check`, `stack_create`; router,
   hints, `INSTRUCTIONS`, `PAGES`, tests; the tool count in README and the site.
3. `sawit new` / `sawit semai`: `SUBCOMMANDS`, `Invocation::Semai`, `crates/core/src/semai.rs`,
   help text, parser tests.
4. `e2e/specs/pages.test.js`, README (Features, shortcut, MCP table, CLI, Build & run, Credits),
   `NOTICE`.
5. Real app: screenshots at 1470 and 720×480, one real create with bun, then `cargo build
   --release`.
