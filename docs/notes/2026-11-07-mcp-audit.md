# MCP audit and code mode (backlog item B1, 2026-11-07)

What `sawit-mcp` offers agents, checked tool by tool against the app's features; the gaps closed;
the names and arguments that don't line up (and why they stay); and code mode, which puts the
whole API behind two tools.

## Summary

- **163 tools before, 168 after:** `git_fetch`, `git_pull` and `git_push` close the one gap an agent
  hit in daily work (the Git tab's remote buttons had no tool); `search_api` and `run` are code mode.
- **Code mode:** `search_api` finds functions by keyword and shows their TypeScript signatures,
  made at run time from the same `#[tool]` definitions the server lists (name, description, input
  schema, hints), so the two can't drift apart. `run` runs a short JavaScript that calls them as
  `sawit.<tool>({...})` and returns only what the script returns, plus its `console.log`.
- **The setting:** `SAWIT_MCP_TOOLS=code` in the client's MCP config lists only `search_api` and
  `run`. Without it (the default) every tool is listed, these two among them. Every tool answers a
  call by its name in either mode, so nothing an agent already does stops working.
- **Tokens on `tools/list`:** 197,073 bytes (about 49,000 tokens) with every tool; 2,307 bytes
  (about 600 tokens) in code mode, 85 times less. The instructions drop from 4,006 to 1,213 bytes.
  Tokens are estimated as bytes / 4; the bytes are exact (`tools_list_size_in_each_mode`).
- **Script engine:** QuickJS through `rquickjs`, already linked for Pele, after measuring Boa (below).

## Names and arguments that don't line up

None of these are renamed: renaming a tool breaks every agent's habits and saved prompts, and code
mode's search finds a function by what it does, whatever its name. They are listed so a future
rename can be done in one go, with the old name kept as an alias (as `render_mermaid` is).

- **Aliases kept:** `render_mermaid` → `render_diagram`, `canvas_add_mermaid` → `canvas_add_diagram`
  (both say "Deprecated"), `app_maximize_terminal` → `app_maximize terminal`.
- **Word order:** `app_network_diagnose` against `diagnose_network`; `shell_files_sync` against
  `sync_agent_settings`; `local_explorer` and `query` have no verb or area prefix.
- **Folder arguments:** `repo` (git), `dir` (`search_files`), `project_dir` (`detect_databases`,
  `list_scripts`), `project` (app tools: which window), `cwd` (`terminal_run`), `location`
  (`stack_create`). Each means something slightly different (a repository, a folder to search, the
  window to act in, where a shell starts), so they stay.
- **Confirmations:** most destructive tools take `confirm: true`; the irreversible deletes
  (`delete_prompt`, `drop_database`, `remove_instance`, `remove_command`, `uninstall_mcp_server`, …)
  take the name typed again. Deliberate, and the README says so.

## Code mode

### How it works

1. `search_api {query: "git commit"}` scores every function on the query's words (name parts first,
   then argument names, then the description) and returns the best eight as TypeScript
   declarations, each argument with its type, whether it is optional and its description, then up
   to 30 more on one line each. No query lists every name by area (about 5 KB).
2. `run {code}` starts a fresh QuickJS runtime on a blocking thread. `sawit.<name>(args)` sends the
   call through the server's own router with the request's context, waits for it, and gives back
   the tool's structured content, else its text parsed as JSON when it is JSON, else the text. A
   tool error throws an `Error` (with `.tool`). A script that is one expression returns its value
   without `return`.
3. Images a call returns (screenshots, exports) are held by number and sent back only when the
   script's result names them, so a script can take ten screenshots and return one.

### Sandbox and limits

- No `require`, `import`, `fetch`, timers, `std` or `os`: QuickJS without its C library, and only
  `sawit` and `console` added. `sawit` is frozen.
- 120 seconds by default (`timeout_secs`, at most 600), Sawit's calls included; 128 MB of heap;
  1 MB of stack. An endless loop is stopped by the interrupt handler.
- Confirmations are the tools' own: a script that calls `delete_prompt` without the id typed again
  is refused exactly as the tool is. `run` is marked destructive and open world, since a script can
  call any tool.
- Calls run one after another (they are synchronous); `await` and `Promise.all` work.

### Boa against QuickJS

Measured on this Mac (M-series, release builds, `lto = "thin"`, stripped) with the same script: 200
host calls passing JSON both ways, then building, stringifying, parsing and reducing a 2,000-row
array, inside an `async` function.

| | QuickJS (`rquickjs` 0.14) | Boa (`boa_engine` 0.22, no `intl`) |
|---|---|---|
| Binary size added (over a 340 KB program without an engine) | +1.0 MB (and +0 MB for Sawit, which links it already) | +6.7 MB |
| Engine start (runtime and context) | 0.13–0.18 ms | 0.30–0.51 ms |
| The script, first run | 8–9 ms | 54–60 ms |
| The script, mean of 20 runs | 7.7–8.2 ms | 54–56 ms |
| `async`/`await`, JSON, ES2020+ | Yes | Yes |

(Two runs each, while a debug build of the app ran beside them, so the times are loose; the ratio,
about 7 times, held in both. The program is
[`js-engine-bench.rs`](2026-11-07-mcp-audit/js-engine-bench.rs) with its
[`Cargo.toml`](2026-11-07-mcp-audit/js-engine-bench.Cargo.toml): build it with no feature, `qjs`
and `boa`.)

QuickJS wins on every count here, and the deciding one is size: `rquickjs` is already in the app (it
runs Pele), so code mode adds no engine to the binary, while Boa would add about 6.7 MB to it, against
B6's goal. Both run `async`/`await`, JSON and the ES2020+ syntax agents write. Boa stays the
candidate if Pele ever leaves QuickJS.

### TypeScript

Scripts are JavaScript. The signatures are written as TypeScript because agents read it best, and
`run`'s description says to leave type annotations out. Stripping types in Rust (`oxc` or `swc`)
would add a large parser for little gain; if agents send TypeScript often, that is the follow-up.

### Done when, checked

- `a_client_in_code_mode_chains_calls_in_one_run`: a real MCP client over an in-memory pipe sees
  only `search_api` and `run`, finds `fill_prompt`, creates and fills a prompt in one `run`, gets a
  refusal from a destructive call without its confirmation, and still calls `list_prompts` by name.
- The e2e spec `code-mode` drives the running app through code mode alone: `terminal_run`, then
  `terminal_read` of the tab and pane it returned, then `app_state`, in one script.
