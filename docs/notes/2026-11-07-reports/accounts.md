## B2 — activity icons

What changed:
- `crates/core/src/activity.rs`: one set of states for every tab (idle, busy, succeeded, failed with the code or a signal, stopped, needs attention), worked out from plain signals (`TerminalSignals`, `browser()`, `canvas()`), with labels, `most_pressing` across panes and `to_json`. Agents count as busy only while they print (3 s quiet window), and the echo of typing is not counted.
- Terminal exit codes: `TermEvent::Exit` carries the child's `ExitStatus` (alacritty's `ChildExit`), kept by the view; `Exited` is emitted once (it could fire twice before). The bell sets "needs attention" until the pane draws with the keyboard in it.
- `crates/app/src/activity.rs`: the icons. Each state has its own glyph (busy: turning `LoaderCircle`; succeeded: `CircleCheck` in success; failed: `CircleX` in danger; stopped: `CircleStop`; attention: `BellDot` in warning), so no state rests on colour or motion alone. The loader turns at 30 fps max, 1.2 s a turn; GPUI's `with_animation` draws the first frame and asks for none under Reduce Motion, so the glyph still says "busy". Over agents' logos the state is a 10 px badge.
- Terminal tabs: the icon, an accessible description with the state ("Exited with code 3"), and the name says "(exited 3)" for a non-zero code. Browser tabs: busy while loading (was a static loader). Canvas tabs: busy while an agent draws (the agent's colour dot stays).
- `app_state`: `terminals[].activity` (state, label, exit_code) and `exit_code` per tab and pane; `browser.tabs[].activity`; `tabs[].activity` for canvases.

Tests: `sawit-core` activity tests (9), app `activity::tests` (each state its own glyph); e2e `terminal: a tab's activity is busy, idle, then failed with its exit code` (new) passes with the other terminal specs (`--filter '^(accounts|terminal):'`: all terminal tests pass).

Design review (better-interface) of the tab icons:

| Severity | Domain | Finding | Status |
|---|---|---|---|
| HIGH (trigger) | Accessibility/UI | State by motion or colour alone | Avoided: a distinct glyph per state, words in the name and the accessible description |
| HIGH (trigger) | Accessibility | Reduce Motion | GPUI's animation element honours it (static first frame, no frames scheduled) |
| LOW | UI | The busy loader keeps the text colour (no accent) | Kept on purpose: quiet beside text |

Verdict: Approve. Not verified: the turning loader and the bell badge seen live in screenshots (the e2e checks state through `app_state`); browser and canvas busy icons were not screenshotted.

## B14 — Accounts page redesign

Design first: `docs/design/accounts.sawit` (frames Accounts / Desktop, Narrow 720×480, Empty, Usage, Diagnostics, Settings). Direction: an instrument panel for limits; graphite neutrals of the app's theme, the accent only on meters and the primary action; signature: meters that say "used" and the reset time on the clock.

What changed (`crates/app/src/accounts/`):
- Page frame (`page.rs`): header with the page icon, "Accounts" and a summary ("3 accounts · 1 active · next resets in 35m"); a vertical, grouped tab list with icons (Role TabList/Tab, ↑/↓ move between tabs, a ring on the selected tab while it has the keyboard); below 1000 px it folds to icons with tooltips; banners sit above the content, not the tabs.
- List (`list.rs`): Add Account at the top opens a panel with a labelled name field, Add and Sign In, Cancel, and Adopt Existing… (with the reason when there is nothing to adopt). Rows grouped under the agent's logo; avatar (tinted disc with the initial), name with a `cpN` badge (no more "1 1"), email or folder (full value in a tooltip), 5h/7d meters with "% used", and a status pill with an icon (Active, At limit, Signed out). Rows are list items with names; the list takes the keyboard (↑/↓ select, Enter opens the terminal) with a focus ring; rows drag to reorder, with Move Up / Move Down in the row's menu (core `Accounts::move_by`, `move_to`).
- Detail (`detail.rs`, capped at 720 px): avatar, name (rename in place, Enter saves), cp badge, plan pill, who it is (tooltip for the full text), Active pill or Set Active, Open in Terminal (primary), ⋯ menu (Set Active, Open in Terminal, Rename, Check Sign-In Again, Move Up/Down, Turn Off Usage Tracking, Remove…). Usage limits: two meter cards (5-hour, 7-day) with "% used", bar, "Resets in …" and the reset on the clock (core `date::when_label`), an icon past warning; "Updated 2 min ago" (warning colour and a clock icon when stale) and Check Usage in the section header; a window that reset shows "No data since the reset at …" with no bar. Tracking off or overridden: one card that says what tracking does with its action. Details: folder (Reveal, Copy Path), how it runs (CLAUDE_CONFIG_DIR), sessions running as it with Continue On…. Empty state with icon, Add Account and Adopt Existing….
- Sign-in card (`card.rs`): step indicator (open the browser → paste the code → done; numbers and checks, not colour alone), time left, labelled code field, Cancel Sign-In.
- Usage tab: period as a segmented control, tiles (tokens, requests, cache hit rate with the change against the period before; core `Totals::cache_hit_rate`, `change_pct`), a table per account and model with right-aligned numbers, running sessions as rows with avatar, Continue On…, End…; empty states with icon and next step.
- Status Line tab: the preview stays at the top while the rest scrolls; chips open a menu with Move Left, Move Right, Remove (keyboard path); Powerline is a switch; per-account switches are settings rows with the reason when disabled.
- Diagnostics: summary pills (passed, warnings, failed, notes), Run Again, Copy Report, one row per check with a pass/warn/fail/info icon and the fix.
- Settings: grouped settings rows (Shell, Shared settings, Limit alerts, Startup) with icon tiles, a description and the control right-aligned; the threshold is a segmented control disabled while alerts are off; install state shown ("Installed in ~/.zshrc"), Remove asks first (`crate::confirm`) for the shell block and the shortcuts.
- Title bar chip: the avatar instead of a dot, "% used" in the label, icons on its menu items.

## C1 — agents and the account pool

Design: the C1 frames in `docs/design/accounts.sawit` (Overview, Detailed, Compare, Timeline, Analytics, Wallet), on the same page as B14.

Research note: the reference demo was not opened from this session (no browser was used); the views follow the feature list in the backlog. Ground rule 7: nothing names it.

Core (`crates/core/src/agent_accounts/`):
- `pool.rs`: providers (Claude Code, Codex), limits (5-hour, weekly), `PoolAccount`, the eight statuses (Plenty left, Running low <25%, Almost out <10%, Limit reached, Not reported, Out of date >15 min, Refresh failed, Sign-in expired), `recommend` (most room, why, the next best, what holds it back, what was skipped), `windows` from readings (peak, hit time), `forecast` (pace against an even pace, projected use, when it runs out), `heatmap` (weekday × hour, local time, hours at the limit), `plan_fit` (too small, fits, could downsize, could cancel, money unused), `move_work`.
- `codex.rs`: Codex accounts are `CODEX_HOME` folders (`~/.codex`, `~/.codex-*`); limits read from the newest session logs' `rate_limits` (primary/secondary, `resets_at` or `resets_in_seconds`). Read-only, no sign-in read. Not verified against a live Codex install (none on this Mac); tested with fixtures of the log shape.
- `readings.rs`: `accounts/readings.sqlite` (0600) keeps readings 120 days (the JSONL history keeps 8), imports the JSONL once, stores a reading when it changes or every 5 minutes; notices on status changes, with read/unread.
- `wallet.rs`: prices (monthly, yearly, included with, not set) with currency and renewal day, top-ups with expiry, renewals, top-ups per month, removed accounts, exchange rates, list prices for known plans as an offer.
- `pool_data.rs`: one `collect` for the app and `sawit-mcp` (the MCP reads only, the app records).
- `terminal::profile_env`: reads only `CLAUDE_CONFIG_DIR` / `CODEX_HOME` from an agent's process environment, to tie a terminal's agent to its account.

MCP: `account_pool` {view: overview|detailed|compare|timeline|wallet|analytics, provider, days}; README table line and tool counts (170 after the merge). Commit `c3279c2a`.

App (`crates/app/src/accounts/`): a "Pool" group first in the page's tab list with Overview, Detailed, Compare, Timeline, Analytics and Wallet (`pool_tabs.rs`), read off the main thread when a pool tab opens and once a minute after (`pool_model.rs`).
- Overview: "Most room right now" with why, what holds it back and the next best; every account with both limits, time to reset and a status pill (icon + words); "Agents in Sawit" (terminal agents with project, tab, account from their environment and their B2 activity; MCP clients on the canvas or browser with what they did last; `agents_seen.rs`); notifications with Mark All as Read; Refresh.
- Detailed: By Provider / By Urgency, a provider filter, the providers' order (Move Up/Down), limits as % used or % left.
- Compare: the pick with Open in Terminal, every account by room with what holds it back and when it resets, the plan-size note and what isn't reported.
- Timeline: Next 24 Hours / This Week; each account's 5-hour and weekly windows on a time axis with the current time, the next window outlined and time at the limit in the danger colour (with a legend); watch list; recent resets (7 days).
- Analytics: 30 / 90 days, all accounts or one; forecast, busiest hour and limit hits; a weekday × hour heatmap with dots for hours at the limit; weekly windows as cells sized by their length and filled by their peak; plan fit as a table sortable by every column; move-work suggestions.
- Wallet: per month / renewing in 30 days / top-ups this month; subscriptions with an inline price editor (Monthly, Yearly, Included, Not Set, amount, renewal day); top-ups with expiry warnings and Delete (asks first); paid top-ups per month for 6 months; removed accounts; exchange rates.

Not built (decided): "hold to reset" and banked resets (neither agent offers resetting a window); credit balances and gateway/promo credit accounts (no agent reports them; top-ups are entered by hand); detecting top-ups from a balance rise (no balance is reported); a detached drag to reorder providers (Move Up/Down instead).

Tests: core `pool` (7), `codex` (3), `readings` (3), `wallet` (4), `pool_data` (1), `terminal::agents::process` profile test; app `pool_tabs` (money, spans, status looks) and `agents_seen` (account mapping); MCP routing, hints and the README/site tool counts; e2e `account pool: every view opens, the pick has the most room, and a price saves` (seeded: the pick is "work" with 59% left, Detailed by urgency orders client, personal, work, Timeline and Analytics render, a monthly price saves to `wallet.json` and shows in the total) passes with all 8 accounts specs.
